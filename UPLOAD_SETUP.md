# Resus Binder document uploader

The private uploader is at `/admin.html`. It publishes PDFs, PNGs and JPEGs to `assets/` in GitHub, and adds their metadata to `uploads.json`. The public site loads that manifest alongside existing entries.

## One-time setup

1. In GitHub, create a fine-grained personal access token scoped **only** to `dresterhuizen-lgtm/resusbinder` with **Contents: Read and write**. Do not paste this token into ChatGPT or the upload form.
2. In Netlify, open Site configuration → Environment variables. Add `RESUS_GITHUB_TOKEN` with the token, and `RESUS_UPLOAD_KEY` with a long, unique random secret (at least 32 characters). Make these available to Functions.
3. Trigger a fresh Netlify deployment. Visit `https://resusbinder.netlify.app/admin.html`, enter the **upload key** (not the GitHub token), choose a PDF and publish.
4. Check that the file appears under Studies/Resus Binder/CCR after deployment.

**Security:** This is a private administrative upload endpoint. Never place tokens in frontend source code or commit them to GitHub. Rotate both secrets if disclosed. The function checks file type, size and credentials. GitHub stores uploaded documents in a public repository: **do not upload patient information or confidential material**.

**Limitations:** GitHub has two sequential writes (binary and manifest); if the manifest write fails, the uploaded file may exist without a catalog entry. Uploaded PDF cards use a generic document placeholder rather than an autogenerated preview thumbnail. For large collections or high-volume uploads, migrate storage to a dedicated object store.
